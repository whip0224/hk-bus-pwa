# 定時巴士到站手機通知系統 (Android + iPhone 跨平台 & 目標時間前後 4 班次版)

為「香港乘車易」加入跨平台（**Android + iPhone**）的**定時車站班次監測與手機通知功能**。當使用者設定目標時間、車站與路線（例如：目標 **`06:30`** · **`觀塘定富街`** · **`258D`**），系統會透過「提前預查與班次時間軸合併機制」，自動捕捉並通知 **最接近 `06:30` 之前的兩個班次** 以及 **`06:30` 之後的兩個班次**（合共 4 個前後班次）。

---

## User Review & Critical Decisions

> [!IMPORTANT]
> 針對您提出「Android 通知方案」以及「顯示設定時間（如 06:30）的前兩個班次與後兩個班次」，架構已作出以下關鍵修改：

- **Key Modification 1 — 「目標時間前 2 班 + 後 2 班」預先採樣時間軸機制 (Pre-Sampling Timeline)**：
  - **技術挑戰**：政府實時 ETA API 每次查詢只回傳「當下未來即將到站的 3 班車」，不會回傳已開走的歷史班次。若等到 `06:30` 才查詢，`06:30` 之前的兩班車已經開走，無法得知；而且你亦需要提早收到通知才趕得上 `06:30` 前的班次。
  - **解決方案**：當設定目標時間為 **`06:30`** 時，系統會自動建立一個 **「提前預查視窗（預設於目標時間前 20~25 分鐘，即 `06:05` 起開始收集）」**：
    1. 在 **`06:05 ~ 06:15`** 先查一次並快取即將在 `06:30` 前到達的班次（例如 `06:16`、`06:26`）與 `06:30` 後的班次；
    2. 在 **`06:15`（首次通知）** 及 **`06:25` / `06:30`（更新通知）** 合併去重所有收集到的班次，精準切分為：
       - **【06:30 前（或最接近）的 2 班】**：例如 `06:16`、`06:26`
       - **【06:30 後的 2 班】**：例如 `06:36`、`06:48`
- **Key Modification 2 — Android (安卓) 原生 PWA 通知與背景執行方案**：
  - **Android Chrome / Edge / Samsung 瀏覽器優勢**：Android 對 PWA 的支援比 iOS 更開放，安裝至桌面或授權通知後，可直接透過 `ServiceWorkerRegistration.showNotification` 發送帶有**震動提示 (`vibrate`)**、**通知欄原地更新 (`tag` + `renotify`)** 及**快速操作按鈕**的原生系統通知。
  - **Android 三重觸發保障**：
    1. **Service Worker 原生通知欄推送 + Wake Lock（出門前保持喚醒模式）**：在目標時間窗口內保持計時器精準運作，自動在 Android 通知欄更新前後 4 班次。
    2. **背景定期同步 (`Periodic Background Sync` / `Visibility` 自動補發)**：支援 Chromium 背景同步事件。
    3. **Android 自動化整合（Bixby Routines 「模式與日常行程」/ MacroDroid / Tasker）**：與 iPhone「捷徑」相同，提供一鍵觸發網址 `?runAlert=<id>`，可由 Android 系統內置日常行程在指定時間背景呼叫。

## 1. Overview & Core Concept

- **What It Does**：
  - 使用者設定「目標到站時間（如 `06:30`）」、「車站（如 `觀塘定富街`）」與「路線（如 `258D`）」。
  - 系統自動換算提前查詢時間，收集並組合出圍繞 `06:30` 的 **前 2 班 + 後 2 班** 實時到站時間，推送清晰通知：
    > **🚌 258D 觀塘定富街（目標 06:30 班次總覽）**
    > **◀ 06:30 前兩班：`06:16`（1分鐘）、`06:26`（11分鐘）**
    > **▶ 06:30 後兩班：`06:36`（21分鐘）、`06:48`（33分鐘）**
- **Target Audience / Persona**：
  - 使用 Android 或 iPhone 的香港通勤族，希望掌握目標時間（如 `06:30`）前後合共 4 班車的完整分佈，以便決定要「提早趕前兩班車」還是「從容乘搭後兩班車」。

## 2. User Experience & Visual Design

### Key User Flows

1. **從路線搜尋結果卡片或常用頁建立「前後班次定時提醒」**：
   - 點擊路線卡片（如 `258D`）底部的 **「設為定時提醒」** 按鈕，彈出設定面板：
     - **路線與方向**：`258D 往 藍田站`
     - **指定上車站**：`觀塘定富街`
     - **目標基準時間 (`targetTime`)**：例如設定 **`06:30`**
     - **首次通知提前量 (`notifyLeadMinutes`)**：預設 **提前 15 分鐘（即 `06:15` 發出首則通知，並在 `06:30` 自動更新一次）**，可選提前 10 / 15 / 20 分鐘或準時觸發。
     - **重複星期**：星期一至五 / 每天 / 自訂。
2. **「前兩班 + 後兩班」時間軸通知與即時看板展示**：
   - 當通知觸發（或點擊「立即測試通知」）時，同時發送**系統通知欄橫幅**及在 App 內顯示**四格班次時間軸卡片**：
     - 左側標示 **「目標時間 (06:30) 前兩班」**（若只剩 1 班則顯示該班及狀態）。
     - 中央顯示 **`06:30` 目標基準線**。
     - 右側標示 **「目標時間 (06:30) 後兩班」**。
3. **Android 與 iPhone 雙平台通知設定指南**：
   - 在第三頁「常用資訊 ➔ 定時到站提醒」內，自動偵測使用者手機系統（Android 或 iOS），顯示對應的一鍵權限開啟、Android 通知欄常駐更新開關、或三星「模式與日常行程」/ iPhone「捷徑」自動化連結複製。

## 3. Key Product Decisions & Trade-Offs

- **Decision 1：如何突破官方 API「每次只給未來 3 班車」的限制，湊齊「前 2 班 + 後 2 班（共 4 班）」？**
  - *Chosen Approach*：實作 **「班次時間軸快取池 (`AlertDepartureHistoryPool`)」**。
    - 由於單次官方 API 最多回傳 3 個未來班次，系統會在目標時間前（例如 `06:05`、`06:15`、`06:25`）進行 2~3 次極輕量採樣，將每次取得的班次依預計到站分鐘（精確至分鐘時間戳）存入本地快取池並自動去重更新。
    - 如此一來，當發送通知時，快取池內便同時擁有 `06:30` 前的 2 個班次（如 `06:16`、`06:26`）與 `06:30` 後的 2 個班次（如 `06:36`、`06:48`），突破單次 API 只回傳 3 班車的限制！
  - *Immediate Test / Single-Shot Fallback*：若使用者在任意時間點擊「立即測試通知」或剛打開 App，系統會以設定的目標時間（或當下時間 + 15 分鐘作為基準線）即時切分目前 API 回傳的班次為「基準時間前/最接近班次」與「基準時間後班次」。
- **Decision 2：Android 與 iPhone 的差異化省電通知策略**
  - *Android 方案*：使用 `navigator.serviceWorker.ready` 配合 `registration.showNotification(title, { body, tag, renotify: true, vibrate: [200, 100, 200], requireInteraction: true })`，讓通知常駐在 Android 鎖屏與狀態欄，並在班次時間更新時直接刷新同一張通知卡片；同時提供可選的「出門前省電常駐監測（Wake Lock）」開關。
  - *iPhone 方案*：結合主畫面 Web Push / `showNotification` 與 iOS「捷徑」URL 自動喚醒。

### Data Model & State

- **`ScheduledArrivalAlert`（更新後的定時提醒結構）**：
  - `id`: 唯一識別碼
  - `label`: 自訂名稱（如 `返工 258D`）
  - `routeId` / `routeNumber` / `operator` / `jointOperator` / `serviceType` / `direction` / `destName`
  - `stopId` / `ctbStopId` / `gtfsId` / `nlbId` / `seq` / `stopNameTc`
  - `targetTime`: 目標基準時間 `"HH:mm"`（例如 `"06:30"`）
  - `notifyLeadMinutes`: 提前多少分鐘開始通知（預設 `15` 分鐘，即 `06:15` 通知你 `06:30` 前後兩班車，並在 `06:30` 更新）
  - `daysOfWeek`: 適用星期 `number[]`
  - `enabled`: 是否啟用 `boolean`
  - `sampledDepartures`: 當日已採樣的班次時間清單 `Array<{ etaTimeStr: string; timestampMs: number; remark: string }>`（用於合併出完整的「前 2 班 + 後 2 班」）
  - `lastNotifiedStage`: 記錄當日已通知階段（`'none' | 'lead' | 'target'`），避免重複洗版
